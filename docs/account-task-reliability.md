# 账号管理可靠性

## 生产可靠性修复（1.15.02.011）

自动重连等待返回 `reconnecting` 和独立 `reconnect` 数据（状态、次数、最大次数、下次执行毫秒时间及原因），账号列表同时提供 `runtimeReconnect`。停止旧 Worker 不再丢失断线原因；手动停止会清除计划与诊断。清理账号既检查运行状态，也排除重连或凭据恢复等待，防止状态落后时误删。

游戏重试达到上限后仍维持有限次语义；内置应用宝的换码失败账号进入 `waiting_credentials`，每分钟串行查询只读健康接口，不在轮询中强刷凭据。只有后台续期成功时间晚于本轮等待开始、凭据未被拒绝且未过期，才按最新配置重新发起一次有限重试周期。手动停止、关闭自动启动或重连、删除账号，以及过时健康响应均不会恢复账号。第三方服务暂不使用内置健康恢复机制。

下线提醒配置增加 `enabled`，旧配置兼容为开启。缺少发送参数返回 `unconfigured`，关闭返回 `disabled`，真实投递才返回 `sent`；提醒历史等待该结果。邮件功能仍需配置邮箱和授权码。

连接状态增加 `connectionDiagnostics`：有界保存编码、发送及响应阶段耗时、Socket 状态和队列深度，不保存请求正文或凭据。诊断帮助区分连接失活位置，不意味着已确认上游断线原因。应用宝错误按安全阶段、类别、数字协议码分类；Login Buffer 失败不再丢失已轮换凭据。

## 应用宝账号自动启动与重试（1.15.02.009）

服务启动时恢复允许自动启动的账号。应用宝账号先换取新的 Code，再创建 Worker；换码失败也会记录失败原因，并按账号独立配置或全局离线重连配置安排重试。等待间隔及最大重试次数以当前设置为准，关闭自动重连时不安排重试。

同一账号的并发启动共享一次换码及其完整结果。手动启动会接管尚未执行的重试计划；手动停止即使尚无 Worker 也会取消计划，换码中停止后不会重新创建 Worker。删除账号、关闭自动启动或改变重连设置后，执行重试前会重新检查资格。

达到最大次数后停止本轮自动重试并保留失败诊断。自动重连创建 Worker 后仍需等待实际游戏连接确认，稳定连接后才清零重试计数。凭据健康页的历史有效标记与运行连接状态分别展示；刷新失败不直接推断凭据已过期，也不视为当前 Code 可用。

## 清理已停止账号

打开清理确认框时固定本次账号名单，后续轮询发现的新账号不会自动加入。只有明确为 `stopped`、且未运行和未连接的账号会列入名单。

确认后，每个删除请求携带 `onlyStopped=1`。服务端重新读取运行状态；启动中、停止中、在线、连接失败或正在批量刷新 Code 的账号返回 `409`，不执行删除。页面列出成功数量及逐项跳过／失败原因，最后统一刷新账号列表。单个账号的手动删除保留原有行为。

## 账号列表更新

同时发起的普通更新合并为一个请求。强制更新会取消旧请求，并阻止旧响应覆盖新结果。请求失败保留现有列表和选中账号，并显示更新失败提示。

设置页在一次轮询完成后才安排下一次轮询；正常间隔 3 秒，失败后逐步退避至 30 秒。页面隐藏时暂停列表轮询，重新可见时立即更新。Code 任务已完成但列表更新失败时，页面分别报告这两个结果。

## 微信 Code 批量任务

- 任务进度写入 `refresh-code-jobs.json`，默认位于源码运行时的 `core/data/`，打包运行时位于可执行文件同级的 `data/`。设置 `FARM_DATA_DIR` 后使用该目录。
- 文件只保存任务所有者、请求号、目标账号 ID／名称、进度和执行结果，不复制完整账号对象或 Code、wxid、token 字段。错误信息会过滤常见的 key、token、wxid、code 查询参数和 Bearer 凭证；任务文件仍包含账号名称及错误摘要，应按普通业务数据管理。
- 每次执行账号前先保存执行意图；执行后保存结果。使用临时文件、同步刷盘及重命名替换，写入失败即停止推进后续账号。
- 服务重启时，排队或执行中的任务转为“已中断”，不会自动重新换码。中断时正在处理的账号标记为“结果未确认”，需先核对其实际状态。
- “重试失败或未执行账号”由服务端根据原任务计算名单，排除成功账号和结果未确认账号，并重新检查当前账号是否存在、可访问及具备刷新身份。
- 页面刷新或暂时断网后继续查询原任务；同一标签页也保留最近一次已结束任务的入口，便于再次刷新页面后查看结果或重试，且已显示过的摘要不重复弹出。提交结果不确定时使用同一请求号重试。任务记录有效期内，相同用户及请求号返回原任务。
- 最多保留 100 条任务记录，非活动任务超过 24 小时后在后续提交时清理；容量满时为新任务淘汰较早的非活动记录。记录被清理后不再提供该请求号的去重或重试能力。
- 任务文件损坏或启动时无法读写时，刷新接口返回 `503`，其他账号接口仍可用。保留原文件，检查数据目录权限或磁盘状态，修复后重启服务；不要通过删除记录来重放结果未确认的账号。

## 验证

网关发送序号在异步编码完成后分配，并与编码后的封包发送同步执行，防止空请求越过慢编码请求后形成发送序号倒序。编码期间使用独立占位键追踪取消及超时，发出前再关联真实序号；允许请求按就绪顺序发送，不等待其他请求的响应。`network-request-lifecycle.test.js` 覆盖慢编码与空请求交错、响应关联、超时、重连隔离及 Socket 写入失败。

在仓库根目录执行（Windows 使用 `pnpm.cmd`）：

```powershell
pnpm.cmd -C core test
pnpm.cmd -C web test
pnpm.cmd -C web exec playwright install chromium
pnpm.cmd -C web test:e2e --reporter=line
pnpm.cmd build:web
```

浏览器回归使用真实账号管理组件、composable 和 store，接口全部模拟，不连接生产后端或实际换码服务。覆盖手机浅色、手机深色及桌面视口下的清理名单、状态变化、列表请求竞争、失败提示、中断恢复、失败重试和长名单弹窗。

如本机已有 Chromium，可设置 `FARM_E2E_CHROMIUM_PATH` 为其可执行文件绝对路径后运行回归，省去浏览器下载；默认仍使用 Playwright 配套的 Chromium。
