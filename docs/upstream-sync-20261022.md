## 配置拆分与迁移

运行数据路径仍遵循 `FARM_DATA_DIR`，默认是 `core/data/`。

| 文件 | 内容 |
| --- | --- |
| `accounts.json` | 账号列表及下一个 ID，结构不变 |
| `store.json` | 全局配置、用户方案、登录设置、通知和界面设置 |
| `account-configs/.format.json` | 账号配置格式版本，目前为 1 |
| `account-configs/<id>.json` | 单个账号的自动化与策略配置 |
| `store.json.<随机标识>.bak` | 拆分前的原始配置备份 |

只有主进程启动时迁移。旧文件非空账号配置先原样备份，再向临时目录逐个写入、读回校验并写格式标记，最后整体重命名发布。发布后的账号文件优先于公共文件中的旧残留，清理残留前额外备份原文件。未知文件名副本会告警跳过；损坏的正式账号配置、缺失格式标记或不支持的版本明确失败，保留文件供修复。

数字 ID 直接作为文件名；其他历史 ID 使用可逆十六进制编码，避免路径穿越、保留名称和大小写冲突。迁移不处理应用宝数据库、消费记录、资源预留和活动状态文件。

一个账号的配置保存不读取或序列化其他账号。相同内容跳过写盘；成功落盘后才发布内存值。保存失败向调用方返回 `STORAGE_WRITE_FAILED`，不会增加设置 revision 或给 Worker 下发失败值。读取和迁移错误分别返回 `STORAGE_READ_FAILED`、`STORAGE_MIGRATION_FAILED`。Worker 在加载 store 前确定账号身份，读取已有配置，接收 `persist: false` 快照；好友运行状态经 IPC 交给主进程保存。

账号列表首次读取后缓存，返回的对象是独立深拷贝，写盘成功后更新缓存。手动编辑运行文件后需要重启，也可由宿主调用 `store.loadAccounts()` 显式重新读取。多个 JSON 文件之间没有跨文件事务；同时更改账号设置和公共设置时应分别确认保存结果。

## 备份和回退

部署前停服备份完整数据目录、应用宝数据库、源码和旧镜像。迁移自动生成的 `.bak` 只包含旧 `store.json`，不能替代完整备份。

旧版本不认识逐账号文件。回退时应停服恢复整套升级前备份，或先把最新的 `account-configs/` 合并回旧版 `accountConfigs` 格式后再运行旧版。仅覆盖旧 `store.json` 无法覆盖已经发布的逐账号配置。迁移失败留下的临时目录及备份，在确认正式配置完整后再人工清理。
