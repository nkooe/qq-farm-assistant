# QQ农场自动助手

> 一个自托管的 QQ 农场多账号自动化管理工具：游戏协议机器人 + Web 控制面板。
> 支持多账号挂机、自动种植收获、好友互动、活动任务、商城购买、图鉴收集，并内置**官方配置自动同步**，让工具数据始终跟上游戏新版本。

**当前版本：`1.15.02.013` · 更新日期：2026-10-24**

QQ / 微信游戏客户端默认版本均为 `1.15.1.4_20261001`，可分别设置。npm 内部版本为 `1.1502.13`，面板及版本接口显示 `1.15.02.013`。

本仓库是可直接运行的纯净源码版。运行时账号、登录凭证、日志、二维码、头像和缓存均保存在本地数据目录，不会随源码提交。

## ✨ 功能特性

### 活动、节令与收集扩展

- **活动大厅**：按账号查看开放时间与玩法，支持赛季、奶茶、萌宠、秋祈、分享、天气、七夕和公益等活动，详情按需加载。
- **节令日历**：节令奖励、已配置题目的正确答案标注、手动答题、季度点亮进度及集齐奖励，参与资格以服务器状态为准。
- **奶茶自动领取**：按账号开关，后台每 5 分钟领取营业收益、工资及已解锁基金奖励，关闭页面继续运行；制作和消费操作保留手动。
- **图鉴等级**：等级奖励、收集点、属性加成及普通 / 装扮 / 活动变异分类，保留种子补录购买。
- **背包保护**：按 UID 区分同名物品堆；支持锁定、到期提醒和条件出售检查，自动出售同样遵守锁定。

接入位置、验证方法和来源见 [活动扩展说明](docs/activity-features.md)。

### 核心：多账号挂机

- **多账号独立 Worker**：每个账号独立进程运行，互不干扰；一个账号异常不影响其他账号。
- **多账号切换**：面板右上角与悬浮导航栏随时切换账号，无需退出重登。
- **一键启动 / 停止**：支持批量启停全部账号。
- **自动重连**：掉线自动重连，达到上限后停止并提示。

### 应用宝扫码与账号恢复

- **打开即显示二维码**：进入“应用宝扫码”标签后自动生成二维码；新增账号和扫码更新共用此流程，二维码失效后可重新生成。
- **首页扫码更新**：应用宝账号未登录时，可直接在首页选择“应用宝扫码更新”；只允许原微信更新当前账号，避免误扫后新增其他账号。
- **应用宝多账号独立运行**：每个扫码账号拥有独立身份、独立 Worker 和独立运行状态，互不覆盖。
- **扫码账号防覆盖**：同一微信重复扫码更新原账号，不同微信扫码会创建新的账号记录。
- **Code 自动刷新续期**：应用宝账号启动、重启和断线重连时自动申请新 Code；在线账号持续按服务端状态续期。
- **统一刷新微信 Code**：面板统一刷新按钮同时支持应用宝账号和旧式微信账号，单个账号失败不会阻塞其他账号。
- **开机恢复上次运行账号**：启动脚本和主程序只恢复上次设置为运行的账号，已停止账号不会被误启动。
- **应用宝服务独立运行**：主面板与应用宝扫码服务由 `start.bat` 一键启动，`tingzhi.bat` 可同时停止两者。

### 每账号代理

- **两种连接模式**：每个应用宝账号可独立选择“直连”或“静态代理”。
- **静态代理协议**：支持 HTTP CONNECT 与 SOCKS5，均可按需填写用户名和密码。
- **扫码前选择出口**：添加应用宝账号时可直接从已有代理配置库选择，扫码、OAuth 回调、用户资料和账号入库全程使用同一出口。
- **完整协议链路**：凭据刷新、HTTPDNS、LongLink、ShortLink 和小程序 Code 请求均遵循该账号的代理设置。
- **严格失败策略**：账号选定的静态代理不可用时直接返回错误，不会静默回退为服务器直连，避免出口意外变化。
- **凭据自动续期**：直连和静态代理账号均支持业务调用时按需刷新及后台到期前续期。

### 农场自动化

- **自动种植 / 收获**：支持背包种子优先、指定种子、播种顺序随机化、延迟控制。
- **库存补差购种**：普通策略先用选中作物的同种背包库存，再按剩余限购、每份数量和预算购买缺口；候选受限时按原策略顺序补种，超时或断线时停止本轮消费。
- **种植提前止损**：识别无收益种植场景，自动止损。
- **多季作物收益口径**：按官方口径精确计算多季作物收益。
- **自动施肥**：智能化肥策略，按容器余量自动补充，支持普通 / 有机化肥。
- **自动除草 / 除虫 / 浇水**：可配置开关。
- **土地升级**：可开启自动升级土地。
- **四格作物优先种植**：自动为 2x2 作物安排合适土地。

### 好友互动

- **自动帮助好友**：浇水 / 除草 / 除虫。
- **自动偷菜（摘取）**：可设置偷取延迟。
- **极速务农**：批量请求优先模式，大幅提升好友操作速度。
- **自动捣蛋（放虫 / 放草）**：连续失败自动暂停至次日。
- **好友管理**：好友列表、搜索筛选、备注、删除、批量删除、黑名单。

- **护主犬信息查询**：批量获取好友护主犬信息。

### 宠物系统（护主犬）

- **购买与激活**：支持购买并激活宠物（田园犬 / 牧羊犬 / 斑点狗 / 柯基 / 护主犬 / 比熊犬）。

- **好友投喂**：查看好友投喂信息并回喂。

### 任务与活动

## 🔄 官方配置自动同步（重点）

游戏会不断新增作物、道具和宠物。本项目内置**配置同步工具**，让本地数据始终跟上官方版本，无需手动补表。

### 工作原理

```
游戏客户端缓存 settings.json
        │  读取 bundleVers（版本号）
        ▼
官方 CDN config.<vers>.json（资源清单）
        │  定位配置表的 uuid + hash
        ▼
import/<uuid>.<hash>.json（XOR 加密）
        │  解密
        ▼
全量 JSON 配置表 → 合并进本地 gameConfig
```

### 服务端自动同步

- 服务启动后 **90 秒**首次检查，之后**每 6 小时**巡检一次。
- **仅在检测到官方版本号变化时**才联网拉取（版本未变时零网络开销）。
- 主模块与 modern 模块共用 `core/src/gameConfig` 中的 `ItemInfo`、`Plant`、`RoleLevel`；现代模块的专用表继续使用原目录。自动同步成功后刷新主进程及 Worker 的两套字典，不重排账号策略；重载失败会在后续巡检重试。
- 同步完成后自动**热加载** `gameConfig`，新道具 / 新作物即时生效。
- 无游戏客户端缓存的部署环境（如纯服务器）会静默跳过，不影响服务运行。

### 手动同步

```bash
# 对比官方与本地差异
node scripts/sync-game-config.js check

# 拉取全量数据并写入（ItemInfo / Plant / RoleLevel）
node scripts/sync-game-config.js sync --write

# 补全缺失物品图标
node scripts/sync-game-config.js icons --write

# 数据 + 图标一起同步
node scripts/sync-game-config.js all

# 列出官方全部配置表
node scripts/sync-game-config.js tables

# 导出单张表
node scripts/sync-game-config.js raw ItemInfo
```

**后续官方更新流程**：打开一次游戏客户端（客户端自动刷新缓存的版本号）→ 服务启动时自动同步，或手动运行 `check` 查看差异 → `sync --write` + `icons --write` 落地。

### 合并策略（保护本地数据）

- 官方字段优先覆盖。
- 仅本地存在的字段（`price` / `price_id` 等）保留。
- 官方已下架的本地独有条目保留不删。
- 官方名称确认后自动清理 `_name_unknown` 占位标记。

## 🚀 快速开始

### 环境要求

- **Node.js 20+**
- **pnpm**（推荐通过 `corepack enable` 启用）
- Docker（可选，仅 Docker 部署需要）

### 方式一：源码运行（推荐本地使用）

```bash
git clone https://github.com/nkooe/qq-farm-assistant.git
cd qq-farm-assistant

corepack enable
pnpm install
pnpm build:web
pnpm dev:core
```

启动后访问：

- 本机：`http://localhost:3900`
- 局域网：`http://<你的IP>:3900`

主面板默认管理员账号：`admin` / `admin`（**首次登录后请立即修改密码**）。应用宝扫码服务账号：`admin` / `123456`。

Windows 也可以直接运行仓库根目录的 `yunxing.bat`：脚本会注册当前用户开机自启，并在后台启动主面板和应用宝服务。运行 `tingzhi.bat` 会停止这两个服务及其子进程。

> **Windows 端口提示**：默认端口 `3900`。原 3007 常被 Hyper-V / WSL 保留导致 `EACCES`，故迁移至 3900。
> 如需修改端口：`ADMIN_PORT=你的端口 pnpm dev:core`（Windows：`$env:ADMIN_PORT="你的端口"; pnpm dev:core`）

### 方式二：Docker 部署

```bash
git clone https://github.com/nkooe/qq-farm-assistant.git
cd qq-farm-assistant

docker compose up -d --build
docker compose logs -f
```

停止并移除容器：

```bash
docker compose down
```

### 方式三：本地打包

```bash
pnpm install
pnpm package:release
```

产物输出在 `dist/` 目录：

| 平台 | 文件名 |
| --- | --- |
| Windows x64 | `qq-farm-bot-win-x64.exe` |
| Linux x64 | `qq-farm-bot` |
| macOS Intel | `qq-farm-bot-x64` |
| macOS Apple Silicon | `qq-farm-bot-arm64` |

程序会在可执行文件同级目录自动创建 `data/`，用于保存账号、用户、日志和缓存等运行时数据。

## ⚙️ 配置说明

### 后台管理

- 面板首次访问需要登录，默认 `admin` / `admin`。
- 首次启动自动创建数据库管理员；注册页创建的账号均为普通用户。管理员通过同一登录入口使用农场功能，并保留账号、卡密、用户和系统管理权限，无需另注册普通账号。
- 仅保留 `admin` 和 `user` 两种角色，已移除硬编码特权登录、专属清库与密码数据导出等旧接口；既有数据库管理员继续使用原密码登录。
- 管理员从 **设置 → 用户管理后面的「后台管理」** 进入 `/admin`，默认打开「配置」；一级菜单为「配置 / 卡密 / 用户 / 日志」，配置内再分「访问控制 / 公告 / 登录页 / 系统连接 / 微信登录」。手机上菜单可左右滑动，切换配置子菜单保留未保存内容。
- **访问控制**中的卡密验证默认开启。关闭后可免卡密注册、跳过到期验证，但封禁和账号数量限制仍生效；管理员始终免卡密。重新开启后，未激活或已到期的普通用户会退出登录，可在登录页的激活/续费入口处理。切换开关不会删除已有卡密或修改原有效期、额度，点击保存并确认后生效。
- **公告**默认关闭，可设置标题、纯文本内容和「每版只显示一次」。开启该项后已读用户不重复弹出，新内容发布后重新提醒；关闭该项则每次登录提醒一次，切换页面不重复弹出。关闭公告保留原内容。
- 应用宝扫码服务默认账号为 `admin` / `123456`，由 `start.bat` 自动配置。
- **部署后请立即修改默认密码。**

### 应用宝账号代理

进入“设置 → 代理设置”可维护静态代理配置库，并为每个应用宝账号单独绑定连接模式。添加应用宝扫码账号时，也可以在生成二维码前选择已有配置。

代理凭据只保存在应用宝服务的本机 SQLite 数据库中，列表接口与页面不会回显密码。`core/data/` 可能包含代理密码、账号凭据等敏感信息，禁止提交到 GitHub。

后台续期默认配置：

```text
YYB_KEEPALIVE_INTERVAL=1m
YYB_KEEPALIVE_AHEAD=45m
YYB_KEEPALIVE_PROXY_AHEAD=5m
```

- 每分钟只做一次轻量数据库检查。
- 直连账号在凭据剩余不足 45 分钟时刷新。
- 静态代理账号默认在剩余不足 5 分钟时刷新。
- 设置 `YYB_KEEPALIVE_INTERVAL=0` 可关闭后台续期。

网络、DNS 或静态代理临时故障会保留账号凭据，后台按 1、2、4、8、16、30 分钟退避重试；手动操作不受该等待时间限制。只有微信明确拒绝 refresh token 时才标记需要重扫。保活不保证 refresh token 永久有效，也不代表游戏协议连接一定可达。

## ❓ 常见问题

**Q：面板打不开 / 端口报 EACCES？**
A：Windows 上 3002-3101 端口区间常被 Hyper-V / WSL 保留。本项目默认使用 3900。若仍报错，执行 `netsh interface ipv4 show excludedportrange protocol=tcp` 查看保留区间，换一个不在其中的端口。

**Q：游戏更新后，新作物 / 新道具不显示？**
A：运行 `node scripts/sync-game-config.js check` 查看差异，然后 `sync --write` + `icons --write`。若服务在运行，它也会自动巡检同步。前提是**本机需要先打开过一次游戏客户端**（用于刷新官方版本号缓存）。

**Q：账号登录不上 / 提示需要更新 Code？**
A：游戏登录 code 有效期较短。在面板中更新账号 Code 后重启该账号。

**Q：Node 报 `getaddrinfo ENOTFOUND gate-*.nqf.qq.com`？**
A：部分 Windows 环境下 Node 的 DNS 解析器读不到系统 DNS。本项目已在 `core/client.js` 内置公共 DNS 兜底，一般无需处理。
